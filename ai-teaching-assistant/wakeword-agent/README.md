# ATA Wake Agent (hardware wake-word)

A packaged Windows voice agent that lets the **Intel always-on DSP** wake the
AI Teaching Assistant when the user says **"Cortana"**. It uses ATA's own
voice-activation host without a separate reference application at runtime.

The agent does **not** do ASR/RAG/LLM/TTS. It only receives the wake from
Windows and hands it to ATA, which then runs exactly the same turn as pressing
the mic button.

Two programs are installed in the same package:

- **Host:** the small UWP application that registers with Windows, arms the
  keyword, and receives Windows background wake events.
- **Worker:** the full-trust .NET executable launched by the host. It reports the
  wake to ATA over HTTP and requests host-microphone capture only when needed.

## How it works

```text
Mic -> Intel DSP (stage-1 keyword model) -> Intel Detection Verification (stage 2)
    -> Windows Agent Activation Runtime (AarSvc_*)
    -> AtaWakeActivationHost (background task, ConversationalAgentTrigger)
    -> AtaWakeAgent.exe --wake (full-trust worker)
    -> POST http://127.0.0.1:7860/api/wakeword/activation {"event":"detected"}
         capture = "browser" -> the open ATA browser UI starts a mic-button turn
         capture = "host"    -> worker POSTs kiosk-core /api/v1/sessions/start (host mic)
```

1. **Keyword binding.** With `UseAarConfigFile=1`, AarSvc decides which app owns
   the DSP keyword from `C:\aarlog\aarconfig.txt`. Each line is
   `DisplayName,{ModelGuid},LCID,AUMID,background`, and a model GUID can be bound
   to **one app only**. Hand-written `SignalDetectionConfigurations` registry keys
   are discarded and regenerated by AarSvc from this file.
2. **Arming.** AarSvc is a demand-start, per-user service. After every sign-in it
   stays stopped until an agent app opens a voice session. Opening the host once
   unlocks the ConversationalAgent Limited Access Feature, registers the
   `AtaConversationalAgentTask` background task, calls
   `SetSignalModelIdAsync(1033)`, and starts AarSvc.
3. **Wake.** On "Cortana", Windows starts the host in the background
   (`OnBackgroundActivated`), even if it is closed. The host prepares the session
   and launches the worker with `--wake`.
4. **Hand-off.** The worker reports the wake to the UI server. If a browser UI
   polled `/api/wakeword/status` in the last 3 seconds, the browser records the
   question (best accuracy). Otherwise the worker falls back to a kiosk-core
   host-microphone session.

The keyword model itself (Cortana, en-US) ships in the Intel Smart Sound OED
driver (`WoV\Ms\m\en-US\*.gna` for the DSP, `*.hsc` for verification). ATA only
references it by IDs and never handles model files.

## Prerequisites

- Intel device with **Intel Smart Sound Technology OED** and **Detection
  Verification** drivers that provide the en-US WoV keyword model.
- Windows **Settings → Privacy & security → Voice activation** and
  **Microphone** turned on.
- **.NET 8 SDK**, **Visual Studio with the Universal Windows Platform
  development workload**, and the **Windows SDK 10.0.26100**.
- An **elevated PowerShell** for install and keyword binding, run as the
  signed-in user.
- Microsoft approval for the ConversationalAgent Limited Access Feature (LAF),
  with a token and attestation covering the package identity you use.

## Microsoft approval and private access configuration

Microsoft requires explicit permission to use this Limited Access Feature.
Request access through the official
[LAF Access Token Request Form](https://go.microsoft.com/fwlink/?linkid=2271232&clcid=0x409).
Identify the ConversationalAgent feature:
`com.microsoft.windows.applicationmodel.conversationalagent_v1`.
Provide the application and publisher information Microsoft requests and follow
the terms supplied with your approval. Approval is not automatic. The API
[documentation](https://learn.microsoft.com/en-us/uwp/api/windows.applicationmodel.limitedaccessfeatures.tryunlockfeature)
defines the attestation as a statement that the publisher has permission to use
the feature; do not copy another publisher's statement or invent approval.

This project's manifest currently declares `Intel.ATA.WakeAgent` with publisher
`CN=ATAWakeAgentDev`. These are development defaults, not a grant of access.
Ask Microsoft which package identity your approval covers. Changing the identity
also affects signing, the package family name, activation IDs, and keyword binding;
do not assume that changing only the token is sufficient.

**Do not publish the token.** Keep it out of source, examples, Git commits,
screenshots, issue reports, logs, build artifacts, and release packages. Confirm
distribution rights separately with Microsoft. Developers building or deploying
a package must establish that their use is approved; do not assume that every
end user of an approved distributed package must obtain a separate token.

The public source and MSIX contain no token. Both host and worker read the same
per-user file after installation:

```text
%LOCALAPPDATA%\Packages\<PackageFamilyName>\LocalState\wake-access.local.json
```

The private input is a JSON file with `token` and `attestation` string fields.
It is a local configuration file, not a cloud service or a new type of key.
The example contains placeholders only; `wake-access.local.json` is ignored by
Git and explicitly excluded from the worker publish output. The configuration
command copies it to the installed package's `LocalState`, outside the MSIX.
This is plaintext storage, not encryption: protect the file according to your
organization's policy. Git ignore prevents normal staging, not forced adds,
manual uploads, or access by your Windows account or administrators.

There are no built-in credentials and no `ATA_WAKE_LAF_TOKEN` or
`ATA_WAKE_LAF_ATTESTATION` environment-variable fallback in this version. Adding
values to ATA's root `.env` does not configure the host or worker. Missing,
placeholder, malformed, or rejected credentials stop hardware activation without
printing their values. Software wake and the manual microphone do not require
this Microsoft token.

## Setup (first time)

First complete ATA's normal [Windows setup](../docs/user-guide/get-started.md).
Then follow these steps with the Microsoft-approved package identity and values.

### 1. Prepare the private file

From the `ai-teaching-assistant` directory in **Windows PowerShell**:

```powershell
cd wakeword-agent
Copy-Item .\wake-access.example.json .\wake-access.local.json
notepad .\wake-access.local.json
```

Replace only the placeholder values locally with your approved token and
attestation. Keep valid JSON escaping for any quotes or backslashes. Do not send
the values to an assistant or paste them into a command line. Do not overwrite an
existing configured file with the example when updating.

Check the file without printing its contents or contacting Microsoft:

```powershell
.\configure-access.ps1 -ValidateOnly
git check-ignore -- wake-access.local.json
```

Validation checks the JSON format, not Microsoft's authorization. The Git command
must report the local file as ignored. No source-code edits are needed to supply
the values.

### 2. Build and install the token-free package

Open **Windows PowerShell as Administrator as the same signed-in user**, navigate
to `ai-teaching-assistant\wakeword-agent`, and run:

```powershell
.\package.ps1 -Install
```

`package.ps1 -Install`:

1. Publishes the worker and builds the UWP host into one signed MSIX
   (`packaging\out\AtaWakeAgent.msix`).
2. Trusts the dev certificate and installs the package.
3. Writes `ATA_WAKEWORD_BACKEND=hardware` and `ATA_WAKEWORD_AGENT_AUMID` to the
   root `.env`.
4. Runs `register-keyword.ps1`, which backs up and rewrites `aarconfig.txt`,
   clears stale bindings, and restarts AarSvc.

The private JSON file is not needed to build, sign, or distribute the token-free
package. Building the package does not itself grant permission to use the feature.

### 3. Reboot and configure the installed package

**Reboot** after keyword binding. On the tested device, restarting AarSvc leaves
keyword detection unavailable until the next boot.

After signing in, use a normal Windows PowerShell for that same user, navigate
to `ai-teaching-assistant\wakeword-agent`, and run:

```powershell
.\configure-access.ps1
```

The command finds the installed package matching the manifest name and publisher,
then copies the validated local JSON into its `LocalState` directory. It does not
start the host or print credential values. To use a file kept outside the checkout:

```powershell
.\configure-access.ps1 -Path 'C:\private\ata-wake-access.json'
```

Keep a secure local copy for replacement or reinstallation. Package removal can
delete its private application data. After configuring access, follow the daily
startup sequence below.

## Every sign-in

1. In a normal Windows PowerShell, navigate to `ai-teaching-assistant` and start
  ATA. Leave this terminal running and wait until the services are ready:

  ```powershell
  .\start_ata.ps1
  ```

2. In a second Windows PowerShell at `ai-teaching-assistant`, open the installed
  host once so Windows can arm the keyword:

  ```powershell
  .\start_wakeword.ps1
  ```

  The launcher uses `ATA_WAKEWORD_BACKEND=hardware` and the installed package's
  `ATA_WAKEWORD_AGENT_AUMID`, written by `package.ps1 -Install` to ATA's `.env`.
  If the backend is `software`, this command starts software wake instead.

3. Open `http://127.0.0.1:7860`, allow microphone access, and click once on the
  page so the browser may play audio. Keep the browser UI open.
4. Say **"Cortana"**, wait for the UI to indicate recording, then ask the question.

For the unchanged development identity, step 2 can alternatively use **Win + R**:

```text
shell:AppsFolder\Intel.ATA.WakeAgent_t2v8cwdf3mgnr!AtaWakeAgent
```

Use the installed AUMID instead if the identity differs. The host is headless and
normally exits shortly after preparing the session. Windows starts it again on a
DSP wake; the host does not need to remain open. Installation alone does not arm
it after a new sign-in, and ATA does not configure automatic sign-in startup.
The launcher reporting success means the package was launched, not that Microsoft
approved access or the DSP is armed. Verify the host log below.

## Updating the agent code

From `ai-teaching-assistant\wakeword-agent`, reinstall without rebinding the
keyword (no AarSvc restart, so no reboot):

```powershell
.\package.ps1 -Install -SkipKeywordBinding
```

The existing per-user configuration normally survives a same-identity update.
After changing credentials, rerun `configure-access.ps1` and then arm the host
again. A reinstall or identity change may require configuration again.

## Restoring the previous keyword binding

Every `register-keyword.ps1` run saves a backup under `C:\aarlog\backup-<timestamp>`:

```powershell
.\register-keyword.ps1 -Restore 'C:\aarlog\backup-<timestamp>'
```

Reboot afterwards.

## Verify

| Check | Command | Expected |
|---|---|---|
| Binding | `Get-Content C:\aarlog\aarconfig.txt` | `Cortana,{86FA368E-...},1033,Intel.ATA.WakeAgent_...!AtaWakeAgent,background` |
| Access configuration | `.\configure-access.ps1 -ValidateOnly` from `wakeword-agent` | Format valid; no credential values displayed |
| AarSvc armed | `Get-Service AarSvc_*` | `Running` (after opening the host) |
| Host log | `%LOCALAPPDATA%\Packages\Intel.ATA.WakeAgent_t2v8cwdf3mgnr\LocalState\wake-host.log` | LAF status `Available` or `AvailableWithoutToken`, then `Session ready: ... SetSignalModelId(1033)=True`; on a wake `Wake background activation` |
| Worker log | `%TEMP%\AtaWakeAgent.log` | `Worker started. Arguments: ... --wake` |
| UI server | `Invoke-RestMethod http://127.0.0.1:7860/api/wakeword/status` | `state` = `waiting`, then `detected` on a wake |

Do not print or attach `wake-access.local.json` when collecting diagnostics.
The UI's waiting state alone does not verify LAF access or a live DSP session.

## Files

| File | Role |
|---|---|
| `activation-host/App.xaml.cs` | UWP entry point: LAF unlock, background-task registration, session preparation, worker launch |
| `WakeAgent.cs` | Worker logic: per-app voice-activation values, binding check, wake handling |
| `AtaBridge.cs` | HTTP calls to the UI server (`/api/wakeword/activation`) and kiosk-core (`/api/v1/sessions/start`) |
| `Program.cs` | Worker CLI: `--arm`, `--wake`, `--trigger` |
| `Package.appxmanifest` | MSIX identity, extensions (`personalAssistantLaunch`, `aboveLockScreen`, `fullTrustProcess`), capabilities |
| `register-keyword.ps1` | Windows voice-activation keyword binding with backup and `-Restore` |
| `package.ps1` | Build, sign, install (`-Install`, `-SkipKeywordBinding`) |
| `configure-access.ps1` | Validate local credentials and provision the installed user's package data |
| `WakeAccess.cs` | Shared host/worker configuration reader and LAF unlock; does not log values |
| `wake-access.example.json` | Public placeholders for the private configuration |

## Worker environment variables

The packaged worker does not read `.env`; it uses the process environment.

| Variable | Default | Purpose |
|---|---|---|
| `ATA_WAKEWORD_UI_BASE_URL` | `http://127.0.0.1:7860` | UI server that receives wake events |
| `KIOSK_CORE_UI_BASE_URL` | `http://127.0.0.1:8012` | kiosk-core for the host-microphone fallback |

## Test the hand-off without the DSP

With ATA running, test the direct HTTP bridge outside the package without a token
or hardware keyword detector:

```powershell
.\bin\Release\net8.0-windows10.0.26100.0\win-x64\publish\AtaWakeAgent.exe --trigger
```

This starts a kiosk-core host-microphone session; it does not test the DSP, Windows
activation, LAF approval, or browser hand-off. `--arm` and `--wake` require package
identity, private configuration, and successful LAF access in this version.

## Known limitations

- Only the **Cortana (en-US)** keyword provisioned in the Intel driver is
  available. A custom keyword needs a new model from Intel/OEM in a driver update.
- Binding ATA unbinds any other app from the same keyword.
- The host must be opened once after every sign-in.
- The host-microphone fallback (no browser UI open) gives poor transcripts on the
  tested SoundWire microphone array; keep the browser UI open.
- `Verify2ndStageAsync` in `WakeAgent.cs` is a stub that always accepts; Intel's
  Detection Verification driver already performs a second-stage check.
- Microsoft approval and local access configuration are required; neither the
  development identity nor a successful package build grants approval.
